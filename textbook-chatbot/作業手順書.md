# 教科書RAGチャットボット 構築手順書

> 対象環境：MacBook M1/M2（8GB RAM）・macOS・Python 3.9・Ollama

---

## 概要

スキャンPDF教科書をOCR処理してベクトルDB化し、
ローカルLLM（Ollama）で質問に答えるRAGチャットボットを構築する手順。

```
質問 → 埋め込み検索 + キーワード検索（ChromaDB）
     → 関連テキストをプロンプトに付与
     → ローカルLLM（gemma3:4b）で回答生成
     → ブラウザ（Flask Web UI）にストリーミング表示
```

---

## 作業前に確認すること

### ハマりポイント① モデルサイズとRAM

| MacのRAM | 使えるモデルの上限 | 推奨モデル |
|---|---|---|
| 8GB | 〜4GB | **gemma3:4b**（2.5GB） |
| 16GB | 〜8GB | gemma4:e4b（9.6GB）も可 |

> ⚠️ 8GBのMacでgemma4:e4b（9.6GB）を使うと**モデルロードに70秒**かかり実用不可。
> 必ず `gemma3:4b` を使うこと。

### ハマりポイント② PDFの種類

```bash
# PDFがテキスト型かスキャン型かを確認
python3 -c "
import fitz
doc = fitz.open('教科書.pdf')
text = doc[5].get_text()
print('テキスト型' if len(text) > 30 else 'スキャン型 → OCR必要')
"
```

> ⚠️ スキャン型PDF（1ページ=1画像）は **OCRなしでは0チャンク** になる。
> 今回の標準理学療法学シリーズはすべてスキャン型だった。

### ハマりポイント③ PythonバージョンとGradio

- Python 3.9では **Gradio が `localhost` にバインドできずエラー**になる
- GradioではなくFlaskを使うこと

### ハマりポイント④ OCRツールの選択

| ツール | 品質 | 速度 | Python 3.9 |
|---|---|---|---|
| **macOS Vision（Swift）** | ◎ 最高 | ○ 1〜3秒/p | ✅ 使える |
| ocrmac | ◎ | ○ | ❌ pyobjc-coreがビルドエラー |
| EasyOCR | △ 文字化け多い | × 10〜15秒/p | ✅ 使えるが低品質 |
| Tesseract | ○ | ○ | Homebrewなしでは導入困難 |

> **正解：Swiftで `ocr_helper` バイナリをコンパイルしてPythonから呼び出す**

## セットアップ手順

### Step 1｜Ollamaとモデルの準備

```bash
# Ollamaの起動確認
curl http://localhost:11434/api/tags

# 推奨モデルをダウンロード（8GB Mac）
ollama pull gemma3:4b   # 2.5GB・日本語医療対応・高速

# 起動確認
ollama list
```

### Step 2｜Pythonパッケージのインストール

```bash
pip3 install sentence-transformers chromadb flask PyMuPDF
```

> ⚠️ Gradioは入れない（Python 3.9との相性問題）

### Step 3｜OCRヘルパーのコンパイル（初回のみ）

```bash
cd ~/textbook-chatbot
swiftc -O ocr_helper.swift -o ocr_helper
```

**`ocr_helper.swift` の内容：**

```swift
import Vision
import Foundation
import AppKit

func recognizeText(imagePath: String) -> String {
    guard let image = NSImage(contentsOfFile: imagePath),
          let cgImage = image.cgImage(forProposedRect: nil, context: nil, hints: nil) else {
        return ""
    }
    let request = VNRecognizeTextRequest()
    request.recognitionLevel = .accurate
    request.usesLanguageCorrection = true
    request.recognitionLanguages = ["ja-JP", "en-US"]
    let handler = VNImageRequestHandler(cgImage: cgImage, options: [:])
    try? handler.perform([request])
    return (request.results ?? [])
        .compactMap { $0.topCandidates(1).first?.string }
        .joined(separator: "\n")
}

let args = CommandLine.arguments
guard args.count == 2 else { exit(1) }
print(recognizeText(imagePath: args[1]))
```

### Step 4｜PDFのインデックス化（初回のみ・時間がかかる）

```bash
# スリープ防止（重要！）
caffeinate -i &   # バックグラウンドでスリープ防止

# インデックス化（バックグラウンドで実行）
nohup python3 ~/textbook-chatbot/index_pdfs.py > ~/textbook-chatbot/index_log.txt 2>&1 &

# 進捗確認
tail -f ~/textbook-chatbot/index_log.txt
```

**処理時間の目安（M2 8GB）：**
- OCR：1〜3秒/ページ
- 28冊・平均300ページ = 約6時間
- 途中停止しても再開可能（20ページごとにキャッシュ保存）

> ⚠️ **電源アダプタを接続するか、バッテリー70%以上で開始すること**

### Step 5｜チャットボットの起動

```bash
python3 ~/textbook-chatbot/chatbot.py
# → ブラウザで http://localhost:7860 を開く
```

> ターミナルを閉じてもバックグラウンド起動できる：
> ```bash
> nohup python3 ~/textbook-chatbot/chatbot.py > ~/textbook-chatbot/chatbot_log.txt 2>&1 &
> ```

## トラブルシューティング

### 「チャンクが0件」になる
→ PDFがスキャン型。OCRが正しく動いているか確認：
```bash
./ocr_helper /tmp/test.png   # テスト画像でOCR動作確認
```

### 「回答が空白」で出典だけ表示される
→ モデルのロード時間が長すぎる（大きなモデルを小さなRAMで使っている）
```bash
# モデルサイズ確認
ollama list
# → 9GB以上のモデルは8GB MacでNG。gemma3:4bに切り替える
```

### 「localhost に接続できません」（Gradio使用時）
→ Python 3.9ではGradioが動かない。Flaskを使う（`chatbot.py`はFlask実装済み）。

### 回答が間違っている
→ モデルの問題。`qwen2.5-coder`系は医療日本語が弱い。`gemma3:4b`を使うこと。

### キーワード検索が遅い
→ 2.2万チャンクの全件スキャンは重い。ベクトル検索だけにするか、
ChromaDBのfull-text searchを利用する（将来的な改善点）。

### OCRの精度が低い
→ macOS Venturer以降ならVision Frameworkが最高品質。
PDFの解像度を上げる（`fitz.Matrix(3.0, 3.0)`で3倍）と精度向上する場合あり。

## 技術構成まとめ

| 役割 | 技術 | 選定理由 |
|---|---|---|
| PDF読み込み | PyMuPDF（fitz） | 日本語PDF対応・軽量 |
| OCR | macOS Vision Framework（Swift） | 日本語精度最高・ローカル動作 |
| 埋め込みモデル | paraphrase-multilingual-mpnet-base-v2 | 日本語対応・無料 |
| ベクトルDB | ChromaDB | ローカル永続化・Python簡単連携 |
| LLM | gemma3:4b（Ollama） | 8GB RAM対応・日本語医療知識あり |
| Web UI | Flask + SSE（Server-Sent Events） | Python 3.9互換・ストリーミング対応 |
